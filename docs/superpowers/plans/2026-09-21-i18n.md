# Internationalisation (English / Portuguese) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the whole site (UI, boot lines, whoami page, all 8 TIL posts, 404 page) in English at `/` and Portuguese (pt-BR) at `/pt/`, with a language switcher in the header.

**Architecture:** Hugo's built-in multilingual mode: two `[languages.*]` blocks, sibling `*.pt.md` content files, `i18n/en.toml` and `i18n/pt.toml` for UI strings, per-language boot lines in config, a `hugo.Sites`-driven switcher partial, and one bilingual `404.html` fed by `data/notfound.toml`. A tiny Python script keeps translations in sync with the English originals.

**Tech Stack:** Hugo 0.166 extended, plain CSS and JS, bash and Python 3.11+ (`tomllib`, standard library only), Playwright MCP tools for visual checks.

**Spec:** `docs/superpowers/specs/2026-09-20-i18n-design.md`

## Global Constraints

- Hugo 0.166 APIs only, and no deprecation warnings: use config key `label` (not `languageName`), `hugo.Sites` (not `site.Languages`), `.Language.Label` (not `.LanguageName`). The check script's build step fails on any `WARN`.
- `defaultContentLanguage = "en"`, `defaultContentLanguageInSubdir = false`: English at `/`, Portuguese at `/pt/`. `[languages.pt]` has `locale = "pt-BR"`, `label = "Português"`, `weight = 2`; `[languages.en]` has `locale = "en"`, `label = "English"`, `weight = 1`.
- `<html lang>` is `site.Language.Locale` (`en`, `pt-BR`).
- Menu stays one root `[menu]` (names `boot`, `whoami`, `TIL` are the same in both languages).
- Boot lines live only in `[languages.<lang>.params.boot]`; there is no root `[params.boot]`.
- `i18n/en.toml` and `i18n/pt.toml` define identical key sets, each as `[key]` + `other = "..."`. Every UI string goes through `{{ i18n "key" }}` or `printf (i18n "key") value`; no user-visible text is hard-coded in JS.
- Portuguese is pt-BR, informal `você`. Fenced code blocks in translated posts are byte-identical to the English ones (comments included). `date`, `tags` and `math` front matter are copied unchanged. Technical terms without a common Portuguese form stay English (goroutine, mutex, errgroup, pipeline, cluster).
- No automatic language redirect and no automatic switching: the header button shows the current language and opens a picker (a `<details>` window, like the palette popup); choosing a language goes to the current page's translation, else to that language's home. The palette choice stays in `localStorage` (shared across languages).
- Shell commands on the 404 page (`cd`, `ls ~`) stay English; only the error line is translated (`Arquivo ou diretório inexistente`).
- Commit messages end with the line `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- `hugo serve` may already be running at http://localhost:1313/ (restart it if it serves a stale CSS bundle after you add a new file). The shell locale is pt_BR.UTF-8; `scripts/check-site.sh` must pass in the ordinary shell. Work on branch `i18n`; never touch `main`.

## File Structure

| File | Responsibility |
|------|----------------|
| `hugo.toml` | Languages, per-language boot lines |
| `i18n/en.toml`, `i18n/pt.toml` | UI strings |
| `data/notfound.toml` | The two languages' 404 error text and placeholder path |
| `layouts/partials/lang_switch.html` | Header language picker (button + window listing the languages) |

| `content/**/*.pt.md` | Portuguese pages |
| `scripts/check-translations.py` | English/Portuguese content sync check |
| `scripts/check-site.sh` | New groups `i18n`, `translations` |

```python
#!/usr/bin/env python3
"""Check that every English content page has an in-sync Portuguese sibling.

    python3 scripts/check-translations.py                  every English page must have a .pt.md sibling
    python3 scripts/check-translations.py --allow-missing  only compare the pairs that exist (work in progress)

For each pair, `date`, `tags` and `math` must match and the fenced code blocks must be byte-identical
(code is not translated, comments included). Standard library only.
"""
import re
import sys
import tomllib
from pathlib import Path

CONTENT = Path("content")
SAME = ("date", "tags", "math")
FENCE = re.compile(r"^```.*?^```", re.S | re.M)
allow_missing = "--allow-missing" in sys.argv[1:]
errors = []


def parts(path):
    """Return (front matter dict, body) of a page with +++ TOML front matter."""
    text = path.read_text(encoding="utf-8")
    if not text.startswith("+++"):
        errors.append(f"{path}: no +++ TOML front matter")
        return {}, text
    end = text.index("+++", 3)
    return tomllib.loads(text[3:end]), text[end + 3:]


for english in sorted(CONTENT.rglob("*.md")):
    if english.name.endswith(".pt.md"):
        continue
    portuguese = english.with_name(english.name[: -len(".md")] + ".pt.md")
    if not portuguese.exists():
        if not allow_missing:
            errors.append(f"{english}: missing {portuguese.name}")
        continue
    en_front, en_body = parts(english)
    pt_front, pt_body = parts(portuguese)
    if "title" not in pt_front:
        errors.append(f"{portuguese}: no title")
    for key in SAME:
        if en_front.get(key) != pt_front.get(key):
            errors.append(f"{portuguese}: {key} is {pt_front.get(key)!r}, the English page has {en_front.get(key)!r}")
    if FENCE.findall(en_body) != FENCE.findall(pt_body):
        errors.append(f"{portuguese}: fenced code blocks differ from {english.name}")

for portuguese in sorted(CONTENT.rglob("*.pt.md")):
    if not portuguese.with_name(portuguese.name[: -len(".pt.md")] + ".md").exists():
        errors.append(f"{portuguese}: no English original")

if errors:
    print("\n".join(errors))
    sys.exit(1)
print("translations in sync")
```

`assets/js/lang-picker.js`:

```js
// The language picker is a <details>, so it opens and closes on its own. This adds the ways the palette
// popup also closes: Esc (focus returns to the button), a click outside, and tabbing out of it. Opening the
// palette popup counts as a click outside, so only one of the two is open at a time.
(function () {
    var picker = document.querySelector(".lang-picker");
    if (!picker) return;
    var summary = picker.querySelector("summary");

    function close() {
        picker.open = false;
    }

    document.addEventListener("click", function (event) {
        if (picker.open && !picker.contains(event.target)) close();
    });

    document.addEventListener("keydown", function (event) {
        if (event.key === "Escape" && picker.open) {
            close();
            summary.focus();
        }
    });

    picker.addEventListener("focusout", function (event) {
        if (picker.open && event.relatedTarget && !picker.contains(event.relatedTarget)) close();
    });
})();
```
