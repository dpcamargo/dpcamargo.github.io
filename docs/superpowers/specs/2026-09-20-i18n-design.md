# Internationalisation: English and Portuguese

Sub-project 2 of 2. Depends on the `.btn` and header styles from `2026-09-20-visual-redesign-design.md`, so it is built after that one.

## Goals

- Serve the whole site in English and Portuguese: UI, boot lines, whoami page and all TIL posts.
- Real per-language URLs, shareable and indexable.

Non-goals: automatic redirect on browser language, more than two languages, translated menu command names.

## Design

### Configuration (`hugo.toml`)

- `defaultContentLanguage = "en"`, `defaultContentLanguageInSubdir = false`. English stays at `/`, Portuguese at `/pt/`.
- `[languages.en]`: `languageName = "English"`, `weight = 1`.
- `[languages.pt]`: `languageName = "Português"`, `locale = "pt-BR"`, `weight = 2`.
- Menus per language (`[languages.<lang>.menus]`). Entries `boot`, `whoami` and `TIL` keep the same names in both languages; only the URLs differ (`/pt/about/`, and so on).
- Boot lines move from `[params.boot]` to `[languages.<lang>.params.boot]` because they are a list. The `pt` block holds the translated lines. Proper names (Go, Java, Python, Full Cycle, FIAP) stay as they are.

### Content

- Sibling files by language suffix: `content/_index.pt.md`, `content/about/index.pt.md`, `content/til/_index.pt.md` and `content/til/<slug>.pt.md` for each of the 9 TIL posts.
- Front matter: `title` is translated. `date`, `tags` and any other fields are copied so both languages stay in sync.
- Body: prose translated. Code blocks, identifiers, commands and URLs unchanged. `whoami` keeps the tone of the English text.
- I write the translations. The site owner reviews the Portuguese before merge.

### UI strings

- New `i18n/en.toml` and `i18n/pt.toml`. Partials use `{{ i18n "key" }}`.
- Covered: sidebar headings (Connect, Stack, Latest TILs), status labels (`status:`, `location:`, `online`, `Brazil`), boot lines built in templates (`Indexed %d TIL entries.`, `Reached target Graphical Interface.`, `System up N years.`), image alt text, aria labels, 404 text, palette popup title and palette button label, language button label.
- `assets/js/theme.js` (palette script) receives its strings through `data-*` attributes on the palette button and popup, rendered with `i18n`. No user-visible text is hard-coded in JS.
- The TIL list date format `dd/mm/yy` is already correct for both languages.

### Language switcher

- New partial `layouts/partials/lang_switch.html`, rendered in the header beside the palette button, as a `.btn` link.
- Label: the other language's short code (`PT` on English pages, `EN` on Portuguese pages), with `lang` and `hreflang` set on the link and a descriptive `aria-label` (for example "Ler em português").
- Target: the current page's translation, from `.Translations`. If the page has no translation, the link goes to the other language's home.
- No redirect on `navigator.language`. The choice is the URL. The palette choice persists in `localStorage` across languages (same origin).
- The unused `layouts/partials/lang.html` is deleted.

### Templates

- `list.html`, `til/list.html`, `side_tils.html`, `boot.html`, `header.html` and menus use `.Site.Language`-scoped data. `absLangURL` and `.RelPermalink` keep internal links inside the current language.
- Hard-coded root links in `header.html` (`{{ .Site.BaseURL }}`) become `{{ "/" | absLangURL }}` so the logo returns to the current language's home.
- `layouts/404.html` uses `i18n`. GitHub Pages serves only the root `/404.html`, so that page shows the message in both languages (English, then Portuguese) instead of picking one.

### SEO

- `head.html` adds `<link rel="alternate" hreflang="…" href="…">` for each translation of the page, plus `hreflang="x-default"` pointing to the English version.
- `<html lang>` already uses `site.Language.Lang`.
- `<meta name="description">` uses the page's language.

## Files touched

- new: `i18n/en.toml`, `i18n/pt.toml`, `layouts/partials/lang_switch.html`, `content/**/*.pt.md` (about, home, TIL index, 9 posts)
- edited: `hugo.toml`, `head.html`, `header.html`, `boot.html`, `side_*.html`, `title.html`, `404.html`, `assets/js/theme.js`
- removed: `layouts/partials/lang.html`

## Testing

- `hugo --gc --minify` builds clean for both languages, no missing `i18n` key warnings (run with `--printI18nWarnings`).
- Script check: every English content page has a `.pt.md` sibling and the same `date` and `tags` in front matter; every `/pt/` page links back to its English counterpart via hreflang.
- Playwright screenshots of every page type in both languages, per palette, at desktop and mobile widths. Check that Portuguese strings do not overflow buttons, sidebar titles or the boot log.
- Manual: switcher on a translated page, on an untranslated page (fallback to home), and from `/404.html`; internal links never jump languages; palette choice survives a language switch.
